# @frontira/design-system 4.8.0

Application contract v1 · component contract v1 · token contract v1

### Added

- Ledger collaboration-surface profile for Miro: a paper-first contract with
  five semantic roles, a workshop object grammar, typography fallbacks and the
  Brand Center governance boundary.
- The two-layer colour split, forced by measurement rather than chosen. Miro's
  API refuses a hex fill on a sticky note (`400`, code `2.0703`, sixteen named
  values only), so authored scaffolding carries Ledger hex exactly while
  participant stickies map semantically. This is why an earlier board was
  flattened to a single image: the SPAR Scoping Canvas is one frame and one
  picture covering 88% of it, with no object anyone can move.
- A token cross-pin in both directions: every Ledger hex the profile names
  must still be that value in the generated token source, so a token edited
  "for Miro" fails the build. That is the only offline gate that can catch
  what #39 forbids.
- A board audit reachable from CI: it catches a flattened canvas by geometry,
  framed zones with no participant objects, and stickies whose colour carries
  no role. Given a board id without `MIRO_TOKEN` the check fails rather than
  skipping, so a credential-less runner cannot go green claiming it inspected
  a board it never fetched.

### Changed

- The component CI block derives its own gate count instead of hardcoding it,
  so adding a gate can no longer leave the success message understating what
  ran.
